# WisdoMark

> 本地运行的**收藏消化助手**（Chrome MV3 插件）：读浏览器收藏或粘贴链接 → 抓正文 → 本地模型提炼「一句话摘要 + 核心观点 + 可行动清单」。
>
> 全本地，零云端。数据不出机器。

---

## 这是什么

收藏了一堆 AI Agent 学习内容，觉得有用但懒得看完，看完也总结不出东西 —— 于是全在收藏夹吃灰。

WisdoMark 把这个死循环拆掉：插件直接读你的收藏夹，用**本地 Ollama** 把每条内容压成一屏能看完的东西，并基于你已有的收藏反过来推断你的学习阶段，给出「接下来该做什么」。

**与「又一个剪藏 demo」的区别**：带**可量化的评测与护栏**。JSON 结构化输出的失败率、分类准确率、摘要幻觉率都有跑分脚本和公开数据。

## 安装

> 当前处于**阶段 2（完整功能）**：单条消化已可用并会自动分类；落库与搜索、批量消化、画像与清单在做。

**1. 放行扩展来源（关键，跳过必失败）**

```bash
setx OLLAMA_ORIGINS "chrome-extension://*"
```

> `setx` 写入的是**用户级**环境变量，对已运行的进程无效 —— 执行后必须**完全退出 Ollama**（托盘图标右键退出）再重新打开。

**为什么必须做这一步**：Ollama 默认只放行 `localhost` 等来源，`chrome-extension://` 不在白名单里。它拦截的是**带 `Origin` 头**的请求，而浏览器只在跨源语义下才附加这个头 —— 插件探活用的 `GET /api/tags` 是简单请求、不带 Origin，所以显示「已连接」；一旦调模型（`POST` + `application/json`）带上 Origin，就必然被拒。**表现就是「状态灯是绿的，一消化就报 HTTP 403」**，很容易误判成模型或代码问题。

**2. 准备本地模型**

```bash
ollama pull qwen3:8b
```

验证：浏览器访问 <http://localhost:11434/api/tags> 应返回模型列表。

**3. 加载插件**

> Edge 与 Chrome 都是 Chromium 内核，用同一套 `chrome.*` API，步骤相同。

| 浏览器 | 扩展管理页 | 加载入口 |
|---|---|---|
| Edge | `edge://extensions/` | 左下角开「开发人员模式」→ 左上角「加载解压缩的扩展」 |
| Chrome | `chrome://extensions` | 右上角开「开发者模式」→ 左上角「加载已解压的扩展程序」 |

选中**本仓库根目录**（即含 `manifest.json` 的那一层，选文件夹本身，不要选里面的文件）。

加载后若工具栏没有图标：点工具栏的扩展图标（拼图）→ 找到 WisdoMark → 选「在工具栏中显示」。

点击 WisdoMark 图标 → 侧栏从右侧展开。

> Edge 已知问题：切到「之前开过侧栏」的标签页时，侧栏不会自动重新显示。这是 Edge 自身的行为，右键扩展图标选「在边栏中打开」即可。

## 使用

侧栏有三个入口：

| 入口 | 做什么 |
|---|---|
| **粘贴链接** | 粘贴任意 http/https 链接。会开一个**后台标签页**读正文，读完自动关掉；正文靠 JS 渲染的页面（知乎、掘金、小黑盒这类）会多等几秒等它出来。留空则消化当前页面。**点进输入框会自动全选**，直接粘下一条即可 |
| **最近收藏** | 读最近 20 条收藏，点任意一条直接消化 |
| **当前页面** | 消化正在看的这一页（另有「只抓正文」按钮，用于排查提取问题） |

结果 = **分类徽标 + 一句话摘要 + 3～5 条要点**。

**分类是自动的**，按「主题领域 → 你读完会去做什么」判定：

| 分类 | 什么内容会落在这里 | 例 |
|---|---|---|
| 技术学习 | 可复用的技术知识、原理、架构、做法、踩坑经验 | 教程、源码分析、经验复盘 |
| 工具与产品 | 某个工具能干什么、怎么用、值不值得用 | 软件推荐、插件测评 |
| 资讯与公告 | 事件本身，读完只需知道 | 版本发布、行业动态、跑分公布 |
| 游戏娱乐 | 一切以游戏为主题的内容 | 攻略、游戏更新公告、活动 |
| 其他 | 以上都不是 | 生活、职场、理财、随笔 |

**要点随内容体裁变化**，不是一刀切的「3 个观点」：

| 内容体裁 | 要点是什么 |
|---|---|
| 观点 / 分析 | 核心观点 |
| 工具 / 应用 / 产品推荐 | 关键事实（推荐了什么、能力或参数、适用与限制） |
| 发布 / 更新公告 / 版本日志 | 关键变化（改了什么、影响什么、要做什么） |
| 教程 / 指南 | 关键步骤 —— **会写到能照着做**：具体命令、参数、路径、执行顺序，以及容易踩的坑 |
| 清单 / 合集 | 最值得关注的具体条目 |

> 详略是按分类分的：`技术学习` 写得最细（每条可到 200 字，因为教程要能照着做），`资讯与公告` 最短（每条 80 字内，知道就行）。这些数值定义在 `shared/prompt.json` 里，改一处两处都变。

只有**没有正文主体**的页面（登录页、错误页、导航页、只有 Cookie 提示）会被判定为无法消化并说明原因——这是设计内的护栏，不是报错。

> 反过来说：**内容体裁不是文章、主题与你的专业方向无关、信息量偏少，都绝不会导致拒收。** 收藏夹里的游戏公告、行业新闻、营销软文一样会被正常压缩。这条边界是实测踩过坑之后收紧的（详见 `AGENTS.md`）。

### 正文写在图片里怎么办（图文帖）

B 站动态、小红书笔记、公众号长图这类内容的干货往往整段整段地画在图片里，DOM 里只有开场白。
**实测**那篇《零基础 AI Agent 学习路线图》：文字只有 1118 字（全是「大家好，今天我要讲七个阶段」），
七个阶段的划分、Track A / Track B 两条路线、每个阶段要用的工具全在 16 张图里 —— 只喂文字，模型只能写出一份空洞的摘要。

所以遇到「正文短 + 正文区大图多」的页面，插件会用**本地离线 OCR**（Tesseract，引擎在 `vendor/tesseract/`）把图里的字认出来，拼进正文再消化：

| 环节 | 做法 |
|---|---|
| 触发条件 | 正文 < 2000 字 **且** 正文区有 ≥2 张大图 —— 正常文章一张图都不会去识别 |
| 挑哪些图 | 短边 ≥200px、不宽扁（比例 ≤1:5）、不在页头页脚、URL 与 class 里没有 logo/avatar/icon/banner 之类的词，一页最多 **8 张** |
| 质量门 | 置信度 <55% 或字数 <8 的整张丢弃；和 DOM 里已有文字重复的也丢弃（图文帖常把正文再截一张图） |
| 上限 | 拼进正文最多 5000 字 |

结果下方会写明这一页的 OCR 账（几张图、认出几张、补了多少字）。实测那篇 B 站动态：**1118 字 → 4223 字**，摘要从「分为 Track A 和 Track B」变成能列出每个阶段要学什么、用什么工具。

> 识别一张图约 1.5 秒，8 张约 12 秒，这期间侧栏会显示进度。
> 封面那种「黑字压在带纹理的浅色背景上」的图会被置信度门挡掉（实测 33%）——它本来就只是标题，正文标题在 `document.title` 里已经有了。

展开「原始输出与重试明细」可以看到每次尝试的原始输出与失败原因。这份记录是为阶段 3 的失败分类留的。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 消化失败，提示 `Ollama 拒绝了扩展来源（HTTP 403）` | Ollama 未放行 `chrome-extension://` | 见「安装」第 1 步；改完环境变量必须**重启 Ollama** |
| 状态灯不绿、提示连接失败 | Ollama 没启动，或端口被占用 | 启动 Ollama；浏览器访问 <http://localhost:11434/api/tags> 确认 |
| 提示「**这个页面没抓到正文**」（只抓到几百字） | 正文靠 JS 渲染，抓取时还没出来；或页面需要登录、拦了自动访问 | 若这一页你自己打开能看到内容：**切到那个标签页，用「当前页面」入口重试** —— 手动打开的页面已经渲染好了，一定能抓到 |
| 提示「**这一页没有可消化的正文**」 | 模型判断这不是内容主体（登录页 / 错误页 / 导航页） | 检查抓到的字数：字数正常说明模型是对的；字数很少见上一条 |
| 后台标签页没自动关掉 | 页面加载超过 25 秒超时，或抓到的正文过少 | **是故意的**，方便你看到底加载出了什么，手动关掉即可 |

## 技术栈

| 层 | 选型 |
|---|---|
| 插件端 | Chrome MV3，原生 JS（无构建工具） |
| 存储 | `chrome.storage.local` + IndexedDB |
| 模型 | 本地 Ollama `qwen3:8b`（`http://localhost:11434/api/chat`，JSON 模式） |
| 图片文字 | 本地 Tesseract.js `chi_sim`（WASM，引擎随仓库走 `vendor/tesseract/`，不联网） |
| 界面 | `chrome.sidePanel` 侧栏 |
| 评测 | Python 独立脚本（与插件解耦） |

**已明确不做**：独立后端、云数据库、云模型（起步阶段）、B 站**视频字幕**（接口已停更；图文动态走 OCR，已支持）、桌面 exe。

## 目录结构

```
manifest.json                    MV3 清单
shared/                          插件与评测脚本的单一来源
  prompt.json                      prompt 模板 + 模型参数
  output-schema.json               输出结构与校验规则
vendor/tesseract/                离线中文 OCR 引擎（约 5.6 MB，见其 README）
src/
  background/                    service worker（ES module）
    service-worker.js               消息路由
    shared.js                       加载 shared/、模板渲染、按 schema 校验
    llm.js                          Ollama 探活与调用（含错误分型）
    page.js                         抓正文（当前页 / 后台标签页）+ 图文帖判据
    digest.js                       消化流水线：解析 → 校验 → 重试 → trace
  content/content-script.js      按需注入，只读 DOM 抓正文与正文大图
  sidepanel/                     侧栏界面（html / css / js）
    ocr.js                          图片文字识别（离线，跑在侧栏）
```

`shared/` 是刻意的设计：prompt、调用参数、输出校验规则都只存一份 JSON，**插件和阶段 3 的 Python 评测脚本读同一份**。否则两套实现会让评测分数失去意义——分数只代表那个 Python 脚本，不代表插件。
